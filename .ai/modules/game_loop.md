# Модуль: Игровой Цикл (Game Loop)

> Ссылка на полный код: [context_supabase_functions.md](../context_supabase_functions.md)  
> Основная функция: `supabase/functions/process-turn/index.ts`

## Обзор

Весь игровой цикл проходит через **одну Edge Function** — `process-turn`.
Она принимает действие игрока и запускает 5-шаговый конвейер.

### Механика Энкаунтеров и Охоты (Step 2 Engine)

Движок рассчитывает динамический порог случайных и целевых встреч:
- **Базовый порог опасности локации**:
  - `safe`: 2%
  - `normal`: 12%
  - `danger`: 35%
  - `lethal`: 65%
- **Множители**:
  - `difficulty`: easy (×0.5), normal (×1.0), hard (×1.5)
  - `timeMult`: от 0.25 до 3.0 (зависит от затраченного времени хода)
  - `intentMult`: ×3.0 при целевом поиске (`encounter_intent: { type: "targeted", target_name: "..." }`)
  - `stealthFactor`: скрытность снижает шанс обнаружения
  - `skillBonus`: модификатор Мудрости (`WIS mod * 0.1`) повышает шанс целевого поиска
- **Защита новичка (Novice Grace Period)**:
  - На сложности `easy` для персонажей 1-го уровня в первые 3 раунда базовый порог случайных стычек = 0%.
  - Стычки возможны только при явной охоте (`encounter_intent: "targeted"`).
- **Минимальный пол урона (Damage Floor)**:
  - При успешном попадании урон всегда составляет минимум 1 единицу (`totalDamage = Math.max(1, totalDamage)`), защищая магов с отрицательным модификатором силы от 0 урона.
- **Безопасный спавн (Safe Starting Location)**:
  - Генератор начальной точки учитывает `danger_level` (`safe`, `normal`, `danger`, `lethal`) и сложность сессии.
  - На `easy` или для 1-го уровня запрещено появление в `danger`/`lethal` зонах (бандитские логова, гиблые топи); спавн гарантируется в безопасных поселениях.
- **Социальное взаимодействие (Talk Handler)**:
  - Диалоги без специальной проверки (`stat_to_check: "none"` или `DC <= 0`) успешны без броска d20.
  - Реплики в дикой местности без NPC трактуются как слова вслух в окружающее пространство.
- При успехе целевого поиска спавнится именно искомое существо, а факты передаются в нарратор.
- **Поддержка прилагательных и биомных эпитетов**: парсер охоты распознаёт конструкции с прилагательными (например, *"болотного василиска"*, *"лесного волка"*, *"свирепого кабана"*, *"пещерного медведя"*), корректно нормализуя имя существа в `target_name`.

## Система кубиков (dice.ts)

```typescript
rollD20()                        // 1-20
rollD20Advantage()               // best of 2d20
rollD20Disadvantage()            // worst of 2d20
performAttackRoll(opts)          // бросок атаки с модификаторами
performSavingThrow(mod, dc)      // спасбросок
rollDamage("1d8+2")             // парсинг и бросок урона
getStatModifier(statValue)       // floor((stat - 10) / 2)
getProficiencyBonus(level)       // ceil(level / 4) + 1
```

**Критический удар** = автоуспех при броске 20.  
**Фамбл** = автопровал при броске 1.

## Сюжетный прогресс (storyProgressEvaluator.ts)

Автоматически проверяет выполнение целей арок после каждого хода.  
Если цель достигнута — продвигает `current_arc_index` в `storyline` JSON сессии.

```typescript
interface StoryArc {
  id, act, title, description,
  goals: string[],
  completed_goals: string[],
  key_npcs, key_locations,
  status: "active" | "completed" | "pending"
}
```

## Раунд мира (npc_world_simulator.ts)

После каждого круга ходов всех игроков — фоновая симуляция жизни мира:
- Берёт до 8 NPC не в текущей сцене
- Один запрос к ИИ на всех → действия (travel/hunt/trade/rest...)
- Применяет мутации: перемещение, XP, предметы, логи
- Пишет системное сообщение-хронику в чат

## Окружение и Память Хода

### 1. Контекст Лора (Lore Context)
- Извлекается до 20 файлов лора из базы (до 8 000 символов, по 2 000 символов на категорию: фракции, магия, география, боги).
- Выжимка первых 1 500 символов подаётся в роутер (Step 1) для точного распознавания сущностей, предметов и географии мира.

### 2. Динамическая Погода (Dynamic Weather)
- Рассчитывается в `index.ts` на основе внутриигрового времени:
  - Сезон (зима, весна, лето, осень) по месяцу.
  - Базовая температура + суточные колебания (день/ночь).
  - Осадки (ясно, переменная облачность, дождь, гроза, снег, метель).

### 3. Память Нарратора и Отказоустойчивость (Step 5 Narrator)
- **Контекст истории**: в Step 5 передаются последние 6 сообщений сессии (до 300 символов каждое) в поле `recent_history` для связности сюжета.
- **Починка JSON**: функция `fixUnescapedNewlinesInJson` экранирует `\n`, `\r`, `\t` внутри строковых литералов ответа ИИ, устраняя синтаксические сбои `JSON.parse`.
- **Прямой парсинг прозы**: если модель вернула развернутый художественный русский текст без JSON-обертки, он автоматически принимается как нарратив.
- **Мульти-ключевой failover (`backup_api_keys`)**: при ошибках авторизации (401/402/403) конвейер немедленно переключается на запасной ключ игрока/хоста.
- **Динамический роутинг моделей**: при исчезновении бесплатных промо-эндпоинтов (404/429) конвейер каскадно пробует актуальные быстрые модели (`meta-llama/llama-3.1-8b-instruct`, `deepseek/deepseek-chat`, `meta-llama/llama-3.3-70b-instruct`, `google/gemini-2.0-flash-001`, `qwen/qwen-2.5-72b-instruct`).
- **Прозрачный мониторинг**: `pipeline.step5` явно возвращает `status: "ok" | "fallback"` и поле `error`, исключая скрытые падения в процедурные заглушки.

## Система Энкаунтеров (step2_engine.ts)

Триггерится при `move`, `search`, или `encounter_intent.type = "targeted"/"random"`.

### Таблица вероятностей по `locations.danger_level`

| danger_level | Базовый шанс | Примеры локаций |
|---|---|---|
| `safe` | 2% | Таверны, города, монастыри |
| `normal` | 12% | Опушки, аванпосты, рынки |
| `danger` | 35% | Руины, катакомбы, пещеры |
| `lethal` | 65% | Ущелья, вулканы, боссовые зоны |

### Модификаторы

| Фактор | Эффект |
|---|---|
| Сложность сессии `easy` | × 0.5 |
| Сложность сессии `normal` | × 1.0 |
| Сложность сессии `hard` | × 1.5 |
| Время действия (30 мин) | × 0.5 (max ×3.0) |
| `targeted` поиск врага | × 3.0 |
| Скрытность (`stealth_factor`) | × stealth_factor |

**Итоговая формула:** `threshold = base × difficulty_mult × time_mult × intent_mult × stealth_factor`

### При триггере (encounter_triggered.triggered = true)

1. Ищем враждебного NPC уже в локации → добавляем fact "готовится к атаке"
2. Если нет — ищем по `world_id + is_hostile=true + tier ≤ encounter_tier+1`
3. Перемещаем NPC в текущую локацию (`location_id = session.current_location_id`)
4. Добавляем в `allNpcs` — следующий ход игрок может атаковать

### encounter_intent в роутере

Роутер (Step 1) определяет:
- `"targeted"` — игрок явно ищет врага ("ищу врагов", "хочу подраться")
- `"random"` — движение по опасной местности
- `"none"` — мирное действие в безопасной зоне

## Мультиплеерное взаимодействие и Отряды (Multiplayer & Party System)

### 1. Точное разрешение адресата (Player vs NPC)
- При обращении или действии роутер и движок сопоставляют имя цели со списком активных живых игроков сессии и локальных NPC.
- Если цель — живой игрок (`player_id`), действие направляется сопартийцу, а системные факты формируют знание для конкретного игрока (`truth.knowledge`).
- Если цель — NPC (`npc_id`), применяется логика социального взаимодействия с NPC (проверки, отношения, отыгрыш характера).

### 2. Формирование и роспуск отряда (Party Formation)
- **Интент объединения (`isPartyInviteOrJoin`)**: фразы "объединиться в отряд", "пойдем вместе", "возьми в отряд", "вступай в наш отряд" активируют автоматическое формирование группы в `sessions.party_groups` и связывают `players.party_id`.
- **Интент роспуска (`isPartyLeave`)**: фразы "покидаю отряд", "выхожу из отряда", "иду один" удаляют игрока из отряда. При количестве участников $\le 1$ группа автоматически расформировывается.

### 3. Синхронное перемещение отряда (Group Movement)
- При смене локации или подзоны лидером проверяется `arePlayersInSameParty(leader, fellow, session)`.
- Синхронно перемещаются **только те сопартийцы, которые находятся в той же стартовой локации/подзоне**.
- Игроки в других локациях или одиночки остаются на своих местах.

### 4. Межпользовательский трансфер предметов (`TRANSFER_ITEM`)
- `transfer_handler.ts` генерирует мутацию типа `TRANSFER_ITEM` с `from_type: "player"` и `to_type: "player"`.
- `apply_turn_mutations` в PostgreSQL атомарно с `FOR UPDATE` списывает предмет у отправителя и начисляет получателю, предотвращая дубликаты и рассинхроны.

### 5. Строгий запрет кукловодства (No Godmoding / No Puppeteering)
- В `step5_narrator.ts` введено жесткое правило 10:
  - ДМ категорически **ЗАПРЕЩЕНО** совершать действия, принимать решения, соглашаться/отказываться или произносить реплики за другого живого игрока.
  - Нарратив для инициатора описывает его слова и оставляет повисшую паузу в ожидании ответа.
  - Нарратив для адресата описывает обращенные к нему слова/жесты, оставляя принятие решения и ответ полностью на усмотрение самого игрока в его ход.
